FROM FIRST SIGN-IN TO YOUR NEXT REVIEW

A study session, step by step

Follow Alex, a fictional learner, through the running application. Expand the examples to see what happens. These are illustrations, not a live demo or an account you can use.

  1. Create your own account

    Run the app using the setup below, then choose Start your quest. Enter your display name, email and a unique passphrase of at least 15 characters. Select Create account.

    Example: first visit and returning sign-in

    ILLUSTRATION · NO SHARED ACCOUNT

    Display name
    Alex
    Email address
    alex@example.test (fictional)
    Password
    Your own private passphrase; never shown in this guide.

    On a later visit, choose Sign in and use the email and passphrase you registered in your running app. The sample address above is not a working login. Password recovery requires email delivery configured by the operator.

  2. Set a manageable study goal

    Choose the bundled certification, a daily goal of 10, 20 or 40 minutes, and an optional target date. Select Open my command center.

    Example: Alex's first dashboard

    Alex chooses 20 minutes and leaves the exam date blank. The command center shows a starting point for learning, review counts and saved sessions. Study history builds from actual answers; a new account has no previous results.

    Check current official exam objectives and availability before booking an exam. The app's bundled objectives are a dated alignment reference.

  3. Answer, then understand the explanation

    Select Start learning, or open the question bank to choose a topic. Read the scenario, select your answer and choose Check answer. Learning feedback explains the concept and each option.

    Example: learning least privilege

    A bundled scenario asks how to let a payroll analyst read salary reports without changing salaries. The learning task is to connect the requested work to the minimum permissions needed.

    After answering, use the explanation to identify the boundary between reading and changing data. This is a walkthrough of existing starter content, not an official exam question.

    In learning mode, feedback appears after an answer. In an active timed mock, explanations wait until the final report.

  4. Turn a mistake into a review

    Missed answers enter your review schedule. When enough questions remain, an item can return after intervening practice; otherwise it is deferred. A quick retry is kept distinct from later recall.

    Example: revisit the idea later

    Alex misses a question, reads the explanation and continues. On a later visit, Weakness recovery and due-review counts help Alex return to that material. A correct repeat does not mean the entire topic has been mastered.

  5. Keep notes and resume your work

    Use Save as flashcard to revisit a concept, or write your own explanation in My Notebook. Notes support folders, tags and revision history. Use Save & exit to leave a study session and return to it later.

    Example: save a personal explanation

    Alex writes a short least-privilege reminder in their own words. Before leaving the notebook, Alex checks that autosave has finished. The running app stores the note and study records in its SQL database.

    Signing in to the same running installation brings back Alex's records. A different installation or device does not automatically have them. Back up the database before moving or updating it.

  6. Try a timed mock when you are ready

    Open Mock exams, choose the available question count and start the timer. Answers save as drafts; correctness stays hidden while the exam is active. Submit to see the report, or let the server-enforced time limit expire.

    Example: learn from the report

    Alex reviews the final explanations and chooses a topic to practise next. The score describes that practice session. It does not predict an official passing result, and the 44-item starter bank cannot supply 90 distinct mock questions.

Start on your own computer

Install Node.js 24 and npm, then clone the master branch:

git clone --branch master https://github.com/jakepanlilio2000/SecQuest.git
cd SecQuest
npm ci
npm run dev

Open http://127.0.0.1:3000. The app creates its local SQLite database on the first API request. Register your own account; no default credentials are supplied.

Already studying with SecQuest? Back up before starting an updated release. Preserve your database, notes and review history. Read the recovery guide before running migrations or changing database engines.
